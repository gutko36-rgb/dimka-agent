# Финансовое планирование: расчётное ядро

## Что готово

Модуль `finance_planning.py` содержит чистые расчёты на `Decimal` и не обращается к Supabase:

- текущий баланс по подтверждённым транзакциям (доходы минус расходы);
- прогноз баланса на заданный горизонт;
- регулярные платежи по дню месяца с корректировкой на короткие месяцы;
- учёт долгов, срок которых попадает в горизонт; просроченный открытый долг считается подлежащим оплате сейчас;
- анализ расходов по категориям относительно заданных месячных лимитов;
- распределение доступной суммы по переданным пользователем весам категорий с точным округлением.

## Правила прогноза

- Используются только уже записанные транзакции.
- Будущая зарплата и другие неподтверждённые доходы не придумываются.
- Регулярные платежи считаются расходами.
- Долг с направлением `owed_by_me` / `i_owe` / `payable` уменьшает прогноз.
- Долг с направлением `owed_to_me` / `they_owe_me` / `receivable` увеличивает прогноз.
- Закрытые/оплаченные долги не учитываются.
- Долги без срока не входят в датированный прогноз; их нужно показывать отдельным списком.
- Распределение денег использует только веса, переданные вызывающим кодом. Модуль не задаёт за пользователя проценты.

## Что ещё не подключено

- В Supabase пока нет таблиц долгов и бюджетов.
- Команда `/forecast` уже использует модуль в режиме read-only: показывает текущий расчётный остаток и известные регулярные платежи на 30 дней. Она не создаёт финансовых записей.
- Для полноценного сценария нужны таблицы долгов/погашений и бюджетов, SQL proposal, команды и подтверждение операций. Текущая `/forecast` прямо сообщает, что будущие доходы и долги пока не учитываются.
- Текущая валюта существующих финансовых таблиц в приложении отображается как RUB; перед включением нескольких валют потребуется отдельная модель.

## Проверки

Unit tests проверяют баланс, прогноз регулярного платежа, просроченный долг, перенос дня 31 на последний день месяца, перерасход бюджета и распределение с округлением.
