# Локальный запуск Димки на Windows 10

Инструкция для владельца проекта, без необходимости разбираться в Python. Все команды ниже вводятся в **PowerShell**. Не отправляй токены и ключи в Telegram, GitHub Issues или переписку.

## Что понадобится

- Windows 10 x64.
- Python 3.11 x64.
- Интернет.
- Один существующий Telegram-бот Димка.
- Ключ Groq и URL/серверный ключ текущего Supabase-проекта.
- Todoist необязателен: без его токена бот запустится, но не покажет задачи.

**Новые Telegram-боты создавать не нужно.** Финансовый и проектный обработчики сейчас являются внутренними модулями одного приложения. Отдельные токены для них не нужны.

## 1. Скачать проект

### Вариант A — проще всего, ZIP

1. Открой репозиторий: https://github.com/gutko36-rgb/dimka-agent
2. Нажми зелёную кнопку **Code**, затем **Download ZIP**.
3. Распакуй архив, например, в `C:\Dimka\dimka-agent`.
4. Открой эту папку в Проводнике.

### Вариант B — через Git

Установи Git for Windows с https://git-scm.com/download/win, затем открой PowerShell и выполни:

```powershell
cd $HOME\Documents
git clone https://github.com/gutko36-rgb/dimka-agent.git
cd dimka-agent
```

Если папка проекта уже есть, обнови её перед работой:

```powershell
git pull
```

Не выполняй `git pull`, если в папке есть собственные незакоммиченные изменения, которые нужно сохранить.

## 2. Установить Python

1. Скачай Python 3.11 для Windows x64: https://www.python.org/downloads/
2. В установщике обязательно отметь **Add python.exe to PATH**.
3. Нажми Install Now.
4. Закрой и снова открой PowerShell.

Проверь установку:

```powershell
py -3.11 --version
```

Ожидается версия вида `Python 3.11.x`. Если команда не найдена, перезапусти компьютер или переустанови Python с отметкой PATH.

## 3. Создать виртуальное окружение

В PowerShell перейди в папку проекта. Например:

```powershell
cd C:\Dimka\dimka-agent
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запретит запуск скрипта активации, выполни только для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

В начале строки PowerShell появится `(.venv)`.

Установи зависимости:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Создать файл настроек .env

В папке проекта найди `.env.example`. Создай его копию с именем `.env`:

```powershell
Copy-Item .env.example .env
notepad .env
```

Заполни только значения справа от знака `=`:

- `TELEGRAM_BOT_TOKEN` — токен **существующего** Димки из BotFather.
- `TELEGRAM_USER_ID` — твой числовой Telegram ID, не имя пользователя.
- `GROQ_API_KEY` — ключ из https://console.groq.com/.
- `GROQ_MODEL` — доступное тебе имя модели из консоли Groq.
- `SUPABASE_URL` — URL текущего проекта Supabase.
- `SUPABASE_KEY` — серверный ключ проекта. Используй только на своём компьютере; никогда не вставляй его в публичный код или браузерный клиент.
- `TODOIST_API_TOKEN` — необязательный токен Todoist.

Остальные настройки пока оставь как в примере. В частности, не включай вручную `FINANCE_DEBT_ENABLED`, `LIFESTYLE_AGENT_ENABLED`, `VOICE_TRANSCRIPTION_ENABLED` или `VISION_OCR_ENABLED`: эти функции зависят от отдельных этапов настройки и могут использовать платные лимиты API.

Сохрани файл и закрой Блокнот. Убедись, что имя файла именно `.env`, а не `.env.txt`. Проводник может скрывать расширения файлов.

**Важно:** не публикуй `.env`, не добавляй его в Git и не присылай содержимое мне. Если токен случайно попал в публичный доступ, отзови его у соответствующего сервиса и выпусти новый.

## 5. Проверить код до запуска

При активном `.venv` выполни:

```powershell
python -m compileall -q .
python -m unittest discover -s tests -v
```

Первой командой проверяется синтаксис Python. Вторая запускает модульные тесты. Некоторые PostgreSQL-интеграционные тесты требуют отдельной тестовой базы и переменной `DATABASE_URL`; не подставляй туда адрес рабочей Supabase-базы и не запускай тесты, которые изменяют данные production.

Если тест завершился ошибкой, сохрани полный текст ошибки из PowerShell. Не пытайся исправлять файлы наугад.

## 6. Запустить Димку

В той же папке и при активном `.venv`:

```powershell
python bot.py
```

Ожидаемое сообщение в консоли: `Личный агент запущен! Доступ разрешён только владельцу.`

Открой существующий чат с Димкой в Telegram и отправь `/start`. Проверь:

1. Бот отвечает на `/start` и показывает меню.
2. Команда `/help` показывает список команд.
3. `/status` (если доступна в текущей версии) показывает состояние подключений.
4. Отправь обычный тестовый вопрос без личных данных и проверь ответ.
5. Проверь чтение задач через `/tasks`, только если добавлен Todoist-токен.
6. Не проводи тестовые финансовые записи и изменения проектов в рабочей базе без необходимости.

Пока окно PowerShell открыто и процесс работает, бот доступен. Для остановки нажми **Ctrl+C**. Закрытие окна PowerShell также остановит локального бота.

## 7. Что означает «бесплатно»

- Сам запуск Python на твоём компьютере бесплатен.
- GitHub для скачивания исходного кода бесплатен.
- Supabase и Groq имеют бесплатные тарифы/лимиты, но они ограничены и могут меняться. Бесплатность не означает неограниченное использование.
- Не подключай платный хостинг, платную базу, платные модели или платные функции без отдельного согласования.
- Локальный запуск работает только пока компьютер включён, есть интернет и открыто окно с ботом.

## 8. Если что-то не работает

- **`py` не найден:** переустанови Python 3.11, отметив Add Python to PATH.
- **`Activate.ps1 cannot be loaded`:** используй команду `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` из шага 3.
- **`No module named ...`:** проверь, что активировано `.venv`, затем повтори `pip install -r requirements.txt`.
- **Ошибка про отсутствующие переменные:** открой `.env`, проверь названия и отсутствие кавычек/лишних пробелов.
- **Telegram не отвечает:** проверь токен, интернет и что этот же токен не используется одновременно другой копией бота. Одновременно запускай только один экземпляр.
- **Groq возвращает ошибку модели/лимита:** проверь имя модели, доступность и текущие лимиты в консоли Groq.
- **Supabase возвращает ошибку:** проверь URL, серверный ключ и состояние проекта. Не запускай SQL-миграции наугад.

При ошибке пришли только текст ошибки и номер шага. Замени или удали из текста любые токены, ключи, URL с секретами и персональные данные.

## Текущее состояние внутренних агентов

Очередь `bot_registry` / `bot_messages` уже развёрнута в подключённом Supabase. Для финансового worker создана отдельная Supabase Auth identity; worker прошёл проверку `diagnostics.echo`, а основной Димка автоматически получает адресованные ему результаты.

Это пока проверка транспорта, а не полноценная финансовая аналитика внутри отдельного worker. Реальные финансовые и проектные обработчики остаются в основном приложении `bot.py`; в worker пока подключён только безопасный тестовый обработчик. Не применяй старый SQL proposal вручную к рабочей базе и не выдавай worker service-role key.

Подробная инструкция по worker, его отдельному `.env.worker`, запуску и smoke test находится в [docs/MULTI_BOT_QUEUE_CLIENT.md](MULTI_BOT_QUEUE_CLIENT.md). Для обычного использования Димки продолжай запускать только `python bot.py`.

Если хочешь включить обработку read-only финансовых вопросов через отдельный worker, сначала запусти `python bot_worker_service.py` в отдельном окне PowerShell и оставь его работающим. Затем добавь `FINANCE_QUEUE_ENABLED=true` в основной `.env` и перезапусти `python bot.py` в первом окне. Без работающего worker этот переключатель включать нельзя. По умолчанию он выключен, поэтому существующее поведение Димки не меняется. Финансовые записи и их подтверждение остаются в основном боте.

Для отдельного агента проектов сначала создай его собственную Supabase Auth identity по инструкции в `docs/MULTI_BOT_QUEUE_CLIENT.md`, затем сохрани его данные в `.env.worker.projects`. Запусти worker в третьем окне PowerShell командами:

```powershell
$env:BOT_WORKER_ENV_FILE=".env.worker.projects"
python bot_worker_service.py
```

Только после успешного запуска добавь `PROJECTS_QUEUE_ENABLED=true` в основной `.env` и перезапусти `python bot.py`. Не включай этот флаг до создания identity и запуска worker. Через очередь передаются только запросы на чтение статуса проекта; любые изменения по-прежнему подтверждаются в основном боте.

## Дополнительные финансы, цели и привычки

После применения миграций `20261110110125_finance_debt_budget.sql` и `20261110110130_lifestyle_agent.sql` можно включить дополнительные команды. В основном `.env` поменяй:

```env
FINANCE_DEBT_ENABLED=true
LIFESTYLE_AGENT_ENABLED=true
```

Перезапусти `python bot.py`. Появятся команды:

- Долги и бюджеты: `/debts`, `/debt_add`, `/debt_pay`, `/budgets`, `/budget_set`, `/budget_weights`, `/budget_weight`, `/allocate`.
- Цели и привычки: `/goals`, `/goal_add`, `/goal_progress`, `/habits`, `/habit_add`, `/habit_log`, `/life`.

Создание долгов, погашение, изменение бюджета, целей и привычек сначала показывается черновиком и требует подтверждения кнопкой. Если миграции ещё не применены, оставь оба флага в `false`.
