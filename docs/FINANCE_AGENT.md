# Финансовый агент — этап 4

## Что делает свободный ввод

Главный обработчик направляет сообщение в финансовый агент только при наличии признаков уже совершённой операции (например: «потратил», «купил», «получил», «заработал») и суммы.

Финансовый агент:
1. Получает текст сообщения, текущую локальную дату пользователя и список его незавершённых проектов.
2. Просит Groq извлечь все отдельные операции в JSON: доход/расход, сумму, категорию, заметку, дату и проект.
3. Проверяет JSON программно. Модель не получает прямого доступа к SQL и не может самостоятельно писать в Supabase.
4. Сопоставляет проект только с точным названием из списка проектов текущего Telegram ID.
5. При неоднозначности задаёт уточнение и не создаёт записей.
6. Показывает пользователю полный черновик и кнопки «Подтвердить запись» / «Отмена».
7. Только после подтверждения сохраняет каждую операцию в `finance_transactions`.
8. После сохранения перечитывает реальные операции месяца и показывает итоги, рассчитанные кодом.

## Защита от дублей

Для одной исходной Telegram update операции получают общий `source_update_id` и порядковый `source_item_index`. Уникальный индекс Supabase по `(telegram_id, source_update_id, source_item_index)` не позволяет повторно вставить операцию при повторной доставке callback или частичном сбое.

## Запросы к финансовой базе

Агент также обрабатывает вопросы обычным языком, например:
- «Сколько я потратил на машину в этом месяце?»
- «Сколько заработал за неделю?»
- «Сколько потратил на проект Пульт?»
- «Покажи расходы за месяц».

Модель извлекает только фильтры запроса (период, тип, поисковые слова, проект). Суммы рассчитываются кодом по строкам Supabase, отфильтрованным по Telegram ID владельца. Такой запрос работает в режиме чтения и не меняет базу. Если проект не удаётся точно сопоставить или вопрос неоднозначен, агент уточняет его.

## Примеры

Сообщение:

```text
Сегодня заработал 15 000 рублей. Из них 5 000 потратил на материалы для проекта «Пульт», 2 000 — на бензин.
```

Ожидаемое поведение:
- три отдельные операции (один доход и два расхода);
- расход на материалы привязан к проекту только если его точное название есть в списке проектов;
- бензин остаётся без проекта;
- до подтверждения ничего не записывается.

Если не указан проект, категория или смысл операции неоднозначен, агент сначала задаёт вопрос.

## Команды и отмена

- `/expense` и `/income` продолжают работать как раньше.
- `/cancel` очищает активное ожидание/черновик и не изменяет уже сохранённые данные.
- Обычный текст о совершённой операции создаёт черновик, а не запись.
- Вызовы финансового агента не перехватывают вопросы о балансе и планы будущих покупок.

## Ограничения текущего этапа

- Черновик хранится в памяти Telegram-сессии. После перезапуска бота его нужно отправить заново.
- Все операции требуют явного подтверждения; автоматическая запись без подтверждения пока намеренно не включена.
- Учёт долгов, текущего остатка банковского счёта и прогноз бюджета — отдельные функции следующего этапа. Агент не должен выдумывать эти значения.
- End-to-end проверка с реальным Telegram/Groq требует локального запуска владельцем; GitHub CI покрывает синтаксис и чистые unit-тесты парсера.
