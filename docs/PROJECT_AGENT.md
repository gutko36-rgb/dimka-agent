# Проектный агент — базовый этап

## Назначение

Проектный агент — внутренний модуль главного Telegram-бота. Supabase остаётся источником данных, Telegram — интерфейсом. Модуль работает только с проектами текущего разрешённого Telegram ID.

## Естественный язык

Распознаются запросы на:
- создание нового проекта;
- добавление этапа, задачи или заметки к существующему проекту;
- изменение описания, цели, статуса, срока или результата;
- просмотр карточки проекта и его текущего прогресса.

Groq возвращает только структурированный черновик. Код проверяет действие, допустимые поля, дату, уверенность и точное совпадение названия с проектом владельца. Если название не совпало однозначно или уверенность ниже порога, бот задаёт вопрос и не пишет в БД.

Для каждого изменения бот показывает предпросмотр. Запись выполняется только после нажатия «Подтвердить». Удаление проекта, записей и материалов через свободный текст запрещено; для удаления остаются отдельные команды с подтверждением.

## Материалы

1. Открой карточку проекта и нажми «Добавить файл» либо отправь `/asset 3`.
2. Следующим сообщением отправь фото или документ.
3. Бот сохраняет Telegram `file_id`, уникальный ID, тип, имя, MIME type, подпись и ID исходного сообщения в существующую таблицу `agent_project_assets`.
4. `/assets 3` или кнопка «Материалы» повторно отправляет сохранённые материалы в Telegram.

Файлы не копируются в новую базу или Supabase Storage. Текущая версия сохраняет ссылочные идентификаторы Telegram и метаданные; OCR, извлечение текста из PDF/DOCX, индексирование содержимого и поддержка ссылок — отдельная следующая задача.

## Финансы и история

Расходы продолжают храниться в `finance_transactions`; проектная связь — `project_id`. Запросы финансового агента могут фильтровать операции по проекту. Удаление проекта удаляет связанные этапы, задачи, заметки и вложения по FK CASCADE, но финансовые операции сохраняются с `project_id = NULL` по FK SET NULL.

## Безопасность

- Каждый запрос к проектам и вложениям фильтруется по `telegram_id`.
- Проект проверяется повторно непосредственно перед записью.
- Изменения требуют явного подтверждения.
- ИИ не получает SQL-доступ и не выполняет запись.
- Схема Supabase в этом этапе не меняется: используется существующая `agent_projects`, `agent_project_items`, `agent_project_assets`.
- Резервная копия дополнена таблицей `agent_project_assets`.

## Проверка

CI запускает `compileall` и `unittest`. После локального smoke test нужно проверить:
- добавление заметки обычной фразой и отмену черновика;
- создание проекта с подтверждением;
- добавление этапа/задачи со сроком;
- прикрепление фото и документа, затем `/assets ID`;
- чтение карточки проекта;
- отсутствие записей при отмене;
- отсутствие доступа к чужому проекту при подмене ID.


## Поиск и лента событий

- `/project_history ID` показывает хронологию создания проекта, этапов, задач, заметок и прикрепления файлов, а также дату последнего изменения карточки.
- В карточке проекта есть кнопка «История».
- `/project_search ID слова` ищет по карточке, проектным записям, подписям к материалам и содержимому последних прикреплённых документов.
- Поддерживаемые форматы: PDF с текстовым слоем, DOCX, TXT, MD, CSV и LOG.
- Ограничения: до 10 МБ на документ, до 5 документов и 25 МБ на один поиск; извлечение текста ограничено 80 страницами PDF и 40 000 символами.
- Файлы скачиваются из Telegram в память на время поиска; извлечённый текст не записывается в Supabase и не сохраняется на диск.
- Сканированные PDF без текстового слоя, OCR изображений, ссылки и версии документов пока не поддерживаются.
- Лента событий собирается из имеющихся `created_at` и `updated_at`; прежние значения полей проекта не архивируются. Для полного аудита потребуется отдельная append-only таблица и отдельная миграция БД.
