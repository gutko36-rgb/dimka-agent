# 🤖 Личный ИИ-агент в Telegram

Персональный ИИ-агент, который помогает управлять жизнью, целями, привычками,
работой, финансами и личными проектами. Работает в Telegram, помнит контекст
между перезапусками, сам инициирует диалог три раза в день и честно
анализирует результаты.

Проект создан по техническому заданию «Помощник по развитию». Агент не
поддакивает ради вежливости: он замечает противоречия между словами и
действиями, не оправдывает откладывание дел и даёт конкретные рекомендации.

---

## ✨ Возможности

### 💬 Диалог с памятью
- Общение на русском языке через Groq.
- История переписки хранится в Supabase и переживает перезапуск бота.
- Долговременная память: агент сам выделяет из сообщений цели, проекты,
  привычки, предпочтения, обязательства, факты и наблюдения.
- Секреты (токены, пароли, ключи) в память не попадают.
- Память и историю диалога можно посмотреть и очистить командами.

### ⏰ Ежедневные опросы
- ☀️ Утренний — планирование дня.
- 🌤 Дневной — контроль промежуточного прогресса.
- 🌙 Вечерний — подведение итогов.
- Время настраивается, учитывается часовой пояс.
- Можно включить/выключить и запустить любой опрос вручную.

### 📈 Отчёты и аналитика
- Отчёт за день, неделю и месяц.
- Точные цифры (сколько опросов отправлено/отвечено, дни без ответов)
  считает код, а не модель.
- Анализ опирается на реальные записи: повторяющиеся проблемы, прогресс по
  целям и проектам, что изменить в следующем периоде.
- Недельный отчёт приходит автоматически по воскресеньям.

### ✅ Todoist
- Чтение задач: просроченные, на сегодня, выполненные.
- Сопоставление задач с планом дня и отчётами.
- Создание задач, перенос сроков и завершение — **только после явного
  подтверждения кнопкой** «Да / Нет».
- Без токена Todoist бот работает, просто не видит задачи.

### 💰 Финансы
- Учёт доходов и расходов по категориям.
- Обязательные ежемесячные платежи и предупреждение о нехватке денег.
- Планируемые покупки и оценка «потяну ли» по реальным цифрам.
- Итоги за неделю и месяц.

### 📁 Проекты
- Проекты с описанием, целью, статусом, сроком и результатом.
- Этапы, задачи и заметки можно добавлять командами или обычным русским сообщением.
- Изменения сначала показываются черновиком и сохраняются только после подтверждения.
- Фото и документы прикрепляются к проекту через Telegram и повторно открываются из карточки.
- Лента событий: создание проекта, этапов, задач, заметок и прикрепление материалов.
- Поиск по карточке, заметкам, подписям и текстовому содержимому PDF/DOCX/TXT/MD/CSV/LOG.
- Прогресс по этапам и задачам; вопросы о состоянии проекта по фактическим записям.
- Поиск файлов выполняется по запросу в памяти; извлечённый текст не сохраняется в Supabase.
- ИИ предлагает план этапов — сохраняется только после подтверждения.
- Расходы связываются с проектом через финансовый агент.
- Напоминания о ближайших сроках проектов, этапов, задач и платежей.

### 🗄 Надёжность
- Ограничение доступа по Telegram ID владельца.
- Резервная копия всех данных файлом (по команде и автоматически по
  воскресеньям).
- Ошибка внешнего сервиса не ломает диалог и не теряет сохранённые данные.

## 🤝 Несколько внутренних агентов

Димка остаётся единственным Telegram-интерфейсом. Специализированные агенты
(финансовый, проектный, рабочий и другие) работают как внутренние модули или
backend workers и не требуют отдельных Telegram-токенов или polling.

Для обмена задачами и результатами предусмотрена адресная очередь в Supabase:
у каждого внутреннего агента свой логический `bot_id` и отдельная ограниченная
Supabase Auth identity/JWT. Главный Димка принимает сообщения пользователя,
маршрутизирует задачи, получает результаты и отвечает владельцу. Внешние
действия по-прежнему требуют явного подтверждения.

Общая Telegram-группа для видимых уведомлений и взаимодействия с владельцем:
`-1004326591308`. Она служит человеко-читаемым пространством уведомлений, а
не машинной шиной: автоматический обмен идёт через backend.

Подробности: [docs/MULTI_BOT_ARCHITECTURE.md](docs/MULTI_BOT_ARCHITECTURE.md).
Сейчас подготовлены архитектура, клиент очереди и общий worker-каркас. SQL
ещё не применён в Supabase, worker не подключён к `bot.py`, и production
поведение Димки не менялось.

## 📂 Структура

Сейчас вся логика собрана в одном файле `bot.py`, разбитом на логические
блоки. По мере роста его можно разделить на модули, как в ТЗ
(`ai.py`, `database.py`, `memory.py`, `todoist.py`, `scheduler.py`,
`analytics.py` и т.д.).

```
.
├── bot.py              # Telegram-интерфейс и диспетчер
├── finance_agent.py    # безопасная обработка финансовых фраз
├── project_agent.py    # безопасное извлечение проектных действий
├── .env                # секреты (не коммитить!)
├── .env.example        # пример конфигурации
├── .gitignore
├── requirements.txt
└── README.md
```

## 🚀 Установка

### 1. Клонировать проект и создать окружение

```bash
git clone <repo-url>
cd <repo-folder>

python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Создать `.env`

Скопируй `.env.example` в `.env` и заполни:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_USER_ID=...
GROQ_API_KEY=...
GROQ_MODEL=...
SUPABASE_URL=...
SUPABASE_KEY=...
# Необязательно:
TODOIST_API_TOKEN=...
```

- **TELEGRAM_BOT_TOKEN** — у [@BotFather](https://t.me/BotFather).
- **TELEGRAM_USER_ID** — твой числовой ID (например, через [@userinfobot](https://t.me/userinfobot)). Бот отвечает только ему.
- **GROQ_API_KEY** и **GROQ_MODEL** — в [консоли Groq](https://console.groq.com/).
- **SUPABASE_URL** и **SUPABASE_KEY** — в настройках проекта Supabase (используй серверный ключ).
- **TODOIST_API_TOKEN** — Todoist → Настройки → Интеграции → Разработчик. Без него бот работает без задач.

### 3. Подготовить Supabase

В SQL-редакторе Supabase нужно создать таблицы. Используются:

`profiles`, `conversations`, `memories`, `daily_surveys`,
`analytics_reports`, `daily_logs`, `ai_insights`,
`finance_transactions`, `finance_payments`, `finance_purchases`,
`agent_projects`, `agent_project_items`.

В текущем подключённом проекте RLS включён на 12 таблицах, но проверка `pg_policies` не обнаружила политик в схеме `public`. Это не открывает таблицы автоматически: при RLS без политик обычный API-доступ закрыт, а серверный `service_role` / secret key обходит RLS. Поэтому бот должен использовать только серверный ключ, ограничивать Telegram ID на сервере и никогда не отдавать ключ клиенту. Не включай публичный доступ и не создавай широкие политики «для всех».

### 4. Зависимости

`requirements.txt`:

```txt
python-telegram-bot[job-queue]>=21
groq
supabase
httpx
python-dotenv
tzdata
```

> `[job-queue]` обязателен: без него не работают ежедневные опросы и напоминания.
> `tzdata` нужен для часовых поясов на Windows.

### 5. Запуск

```bash
python bot.py
```

В консоли появится «Личный агент запущен!». Открой бота в Telegram и нажми
`/start`.

### Меню внизу

| Кнопка | Что делает |
|---|---|
| ✅ Задачи | задачи Todoist: просроченные, на сегодня, выполненные |
| 📈 Отчёты | отчёт за день / неделю / месяц |
| 💰 Финансы | доходы и расходы за месяц |
| 📁 Проекты | список проектов и их прогресс |
| 🧠 Память | что агент о тебе помнит |
| 📊 Статистика | сколько данных в таблицах |
| ⏰ Расписание | время опросов, часовой пояс, вкл/выкл |
| 📋 Статус | состояние бота и подключений |
| ❓ Помощь | полный список команд |

Кнопки открывают действия прямо в чате. Если нужно что-то напечатать (сумму,
название), бот попросит это одним сообщением.

### Основные команды

**Опросы и расписание**
```

/timezone Europe/Moscow          # часовой пояс
/surveys on | off                # включить / выключить опросы
/survey morning|noon|evening     # запустить опрос сейчас
```

**Память и история**
```
/memory            # что я помню
/forget 3          # удалить запись памяти №3
/reset             # очистить историю диалога (память остаётся)
```

**Отчёты**
```
/day  /week  /month
```

**Todoist**
```
/tasks             # задачи из Todoist
```
Изменения задач предлагаются ИИ и выполняются только после подтверждения
кнопкой.

**Финансы**
```
/expense 350 еда обед
/income 50000 зарплата
/finance           # итоги за месяц
/finance week      # итоги за неделю

/payment 15000 5 Аренда   # платёж каждый месяц 5-го

/buy 80000 Ноутбук

/buy_check 2       # оценить, потяну ли
/buy_done 2        # купил (запишется расход)
/buy_del 2
```

**Проекты**
```

/projects

/project_set 3 deadline 31.12.2026

/p_done 15   /p_undo 15   /p_del 15

/asset 3                  # прикрепить следующее фото или документ

/project_del 3 да

/deadlines   # ближайшие сроки
/backup      # резервная копия файлом
```

## 🧠 Как работает память

1. Агент получает сообщение и по ключевым словам решает, есть ли в нём
   устойчивая информация.
2. Модель выделяет записи строго в формате
   `{"memories": [{"category", "content", "importance"}]}`.
3. Записи проверяются (категория, непустой текст, важность 1–5, отсутствие
   дублей) и сохраняются в `memories`.
4. При каждом ответе активная память подмешивается в системный промпт.

Сохраняются только **устойчивые** сведения. Разовые планы, шутки и текущие
дела в память не попадают — для них есть опросы и отчёты.

## ⚠️ Ограничения и важные замечания

- Агент **не финансовый консультант**. Оценка покупок — прикидка по твоим
  записям, а не рекомендация.
- Агент считает задачу выполненной только по словам пользователя или по
  отметке в Todoist.
- Данные модели могут быть неполными: если записей мало, отчёт честно об этом
  скажет.
- Финансовые записи из команд `/expense` и `/income` защищены от повторной обработки одного Telegram update. Для привязки операции к проекту укажи `project=ID`, например `/expense 1500 материалы пластик project=3`.
- Свободная фраза с завершённой операцией (например, «потратил 500 рублей на продукты») распознаётся отдельным финансовым модулем. Бот показывает черновик и записывает операции только после явного подтверждения кнопкой. Неоднозначные сведения уточняются; отмена не меняет базу. Вопросы вроде «Сколько я потратил на машину в прошлом месяце?» обрабатываются в режиме чтения: суммы считаются по данным Supabase.
- Для работы ежедневных опросов нужен пакет
  `python-telegram-bot[job-queue]`.

## 🔒 Безопасность

- Бот отвечает **только** владельцу (`TELEGRAM_USER_ID`); остальным —
  «Доступ запрещён».
- Все ключи — в `.env`, файл исключён через `.gitignore`.
- Supabase — серверный ключ и Row Level Security.
- Любое изменение Todoist требует подтверждения кнопкой.
- Резервные копии не содержат секретов.

`.gitignore`:

```gitignore
.env
.venv/
__pycache__/
*.pyc
backup-*.json*
```
